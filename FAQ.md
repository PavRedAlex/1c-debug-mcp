# FAQ — Часто задаваемые вопросы

## Общие вопросы

### Что такое MCP сервер?

MCP (Model Context Protocol) — это протокол для интеграции AI-ассистентов с внешними инструментами и сервисами. MCP сервер предоставляет набор инструментов, которые AI может вызывать для выполнения задач.

### Зачем нужен 1C Debug MCP Server?

Этот сервер позволяет AI-ассистентам (Claude, Kiro и др.) управлять отладкой 1С приложений: устанавливать точки останова, выполнять пошаговую отладку, просматривать переменные. Это упрощает анализ и отладку кода 1С с помощью AI.

### Какие версии 1С поддерживаются?

1С:Предприятие 8.3 с поддержкой HTTP Debug Protocol (dbgs.exe). Протестировано на версии 8.3.27.

## Установка и настройка

### Как запустить сервер отладки 1С?

```bash
dbgs.exe --port=1550 --addr=localhost
```

Сервер отладки обычно находится в папке установки платформы 1С.

### Где взять infobaseAlias?

`infobaseAlias` — это имя информационной базы из файла `ibases.v8i`. 

**Для локальной базы:**

Откройте файл `ibases.v8i` и найдите строку вида:

```
[DefAlias]
Connect=File="C:\InfoBases\MyBase";
```

В данном случае `infobaseAlias` = `DefAlias`.

**Для серверной базы:**

Используйте имя базы на сервере 1С:Предприятие. Например:

```
[production_base]
Connect=Srvr="server1c";Ref="production_base";
```

В данном случае `infobaseAlias` = `production_base`.

### Как найти objectID модуля?

`objectID` — это GUID объекта из метаданных конфигурации. Его можно найти в XML файлах выгруженной конфигурации:

1. Выгрузите конфигурацию в файлы (EDT или Конфигуратор)
2. Откройте XML файл модуля (например, `CommonModules/ОбщегоНазначения.xml`)
3. Найдите атрибут `uuid` в корневом элементе

Пример:
```xml
<MetaDataObject xmlns="..." uuid="4eee25b1-2da6-459b-953b-4c8d519c9bce">
```

### Нужно ли выгружать конфигурацию?

Не обязательно, но рекомендуется. Если настроить `ONEC_CF_PATH`, MCP сервер будет автоматически резолвить `objectID` в человекочитаемые имена модулей.

Без метаданных вы увидите только GUID:
```
objectID: 4eee25b1-2da6-459b-953b-4c8d519c9bce
```

С метаданными:
```
CommonModule.ОбщегоНазначения
```

## Отладка

### Почему точки останова не работают для внешних обработок?

Это ограничение протокола отладки 1С. Внешние обработки имеют динамический `objectID`, который генерируется при каждом открытии. Платформа не может сопоставить установленную точку с runtime модулем.

**Решение:** Используйте `pause` (breakOnNextLine) + пошаговое выполнение.

### Как отладить внешнюю обработку?

```typescript
// 1. Установить паузу
await mcp_1c_debug_pause({ targetId: "..." });

// 2. Выполнить действие в обработке (нажать кнопку)

// 3. Дождаться остановки
const stop = await mcp_1c_debug_wait_for_stop();

// 4. Пошаговое выполнение
await mcp_1c_debug_step_in({ targetId: stop.targetId });
```

### Как отладить серверную процедуру?

Серверные процедуры (с директивой `&НаСервере`) выполняются в отдельной цели отладки типа `ServerEmulation`. Нужно:

1. Получить список целей через `get_targets()`
2. Найти цель с типом `ServerEmulation`
3. Использовать её `targetId` для установки точек и отладки

### Почему не срабатывает точка останова?

Возможные причины:

1. **Неправильный objectID** — убедитесь что используете правильный GUID из метаданных
2. **Неправильный moduleType** — проверьте тип модуля (CommonModule, ObjectModule, FormModule и т.д.)
3. **Внешняя обработка** — точки для EPF не работают, используйте pause
4. **Код не выполняется** — убедитесь что код действительно вызывается в 1С
5. **Другой отладчик подключён** — закройте отладчик в Конфигураторе

### Как узнать на какой строке остановилось выполнение?

Используйте `wait_for_stop()` — он возвращает информацию об остановке:

```typescript
const stop = await mcp_1c_debug_wait_for_stop();
console.log(`Stopped at ${stop.moduleName}:${stop.lineNo}`);
console.log("Call stack:", stop.callStack);
```

### Можно ли изменить значение переменной во время отладки?

Нет, протокол отладки 1С не поддерживает изменение значений переменных. Можно только просматривать их через `get_variables()` и вычислять выражения через `evaluate()`.

## Ошибки

### Ошибка "ibInDebug — another debugger is connected"

Другой отладчик уже подключён к информационной базе. Закройте отладчик в Конфигураторе и повторите попытку.

### Ошибка "notRegistered — check infobaseAlias"

Неправильный `infobaseAlias` или требуются credentials. Проверьте:

1. Правильность `infobaseAlias`:
   - Для локальной базы: обычно `DefAlias` (проверьте в ibases.v8i)
   - Для серверной базы: реальное имя базы на сервере (например, `production_base`)
2. Если база требует пароль, передайте параметр `password` в `attach()`

### Ошибка "Timeout waiting for stop event"

Выполнение не остановилось в течение указанного таймаута. Возможные причины:

1. Точка останова не сработала (см. "Почему не срабатывает точка останова?")
2. Код не выполнялся
3. Слишком короткий таймаут — увеличьте значение

### Ошибка "No active session"

MCP сервер не подключён к серверу отладки. Вызовите `attach()` перед использованием других инструментов.

### Ошибка "Failed to connect to debug server"

Сервер отладки (dbgs.exe) не запущен или недоступен. Проверьте:

1. Запущен ли dbgs.exe на целевой машине
2. Правильность URL в `ONEC_DEBUG_URL`:
   - Локально: `http://localhost:1550`
   - Удалённо: `http://server-ip:1550`
3. Доступность порта (не заблокирован файрволом)
4. Сетевую связность (для удалённого сервера): `ping server-ip`
5. Правильность IP адреса и порта

**Для удалённого сервера:**
- Убедитесь что dbgs.exe запущен с `--addr=0.0.0.0`
- Проверьте файрвол на сервере: `netsh advfirewall firewall show rule name=all | findstr 1550`
- Проверьте доступность порта: `telnet server-ip 1550`

## Производительность

### Как ускорить резолвинг модулей?

MetadataProvider кэширует результаты резолвинга. При первом запуске может быть медленно (парсинг XML), но последующие вызовы будут быстрыми.

### Сколько целей отладки можно подключить одновременно?

Протокол поддерживает множественные цели (ManagedClient, ServerEmulation, и др.). MCP сервер автоматически подключается ко всем доступным целям при `autoAttach: true`.

### Влияет ли отладка на производительность 1С?

Да, отладка замедляет выполнение кода. Особенно заметно при большом количестве точек останова или частом вызове `evaluate()`.

## Разработка

### Как добавить новый инструмент?

1. Создайте файл в `src/tools/`
2. Реализуйте функцию-обработчик
3. Зарегистрируйте инструмент в `src/index.ts` через `server.tool()`

Пример:
```typescript
// src/tools/myTool.ts
export function createMyTool(debugClient: DebugClient) {
  return async (args: { param: string }) => {
    // Ваша логика
    return {
      content: [{ type: "text" as const, text: JSON.stringify({ result: "ok" }) }]
    };
  };
}

// src/index.ts
import { createMyTool } from "./tools/myTool.js";
const myTool = createMyTool(debugClient);
server.tool("my_tool", "Description", { param: z.string() }, myTool);
```

### Как отладить сам MCP сервер?

Логи пишутся в `dist/1c-debug.log`. Для просмотра в реальном времени:

```bash
tail -f 1c-debug-mcp/dist/1c-debug.log
```

Также можно использовать `raw_request` для отправки произвольных XML запросов и анализа ответов.

### Как запустить тесты?

```bash
npm test              # Все тесты
npm run test:watch    # Watch режим
```

### Где документация по протоколу отладки 1С?

Официальной документации нет. Используйте:

1. Исходники [onec-debug-adapter](https://github.com/akpaevj/onec-debug-adapter) (C# реализация)
2. Анализ протокола в `vault/knowledge/logic/` этого проекта
3. Инструмент `raw_request` для экспериментов

## Интеграция

### Как использовать с Claude Desktop?

Добавьте конфигурацию в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "1c-debug": {
      "command": "node",
      "args": ["path/to/1c-debug-mcp/dist/index.js"],
      "env": {
        "ONEC_DEBUG_URL": "http://localhost:1550",
        "ONEC_INFOBASE_ALIAS": "DefAlias"
      }
    }
  }
}
```

### Как использовать с Kiro?

Добавьте конфигурацию в `.kiro/settings/mcp.json`:

```json
{
  "mcpServers": {
    "1c-debug": {
      "command": "node",
      "args": ["/path/to/1c-debug-mcp/dist/index.js"],
      "env": {
        "ONEC_DEBUG_URL": "http://localhost:1550",
        "ONEC_INFOBASE_ALIAS": "DefAlias",
        "ONEC_CF_PATH": "/path/to/configuration"
      }
    }
  }
}
```

### Можно ли использовать без AI-ассистента?

Технически да, но это не рекомендуется. MCP сервер предназначен для интеграции с AI. Для прямой отладки используйте встроенный отладчик Конфигуратора или [onec-debug-adapter](https://github.com/akpaevj/onec-debug-adapter) с VS Code.

## Безопасность

### Безопасно ли использовать в продакшене?

**Нет!** Сервер отладки (dbgs.exe) предназначен только для разработки. Не запускайте его на продакшен серверах.

### Нужен ли пароль для подключения?

Зависит от настроек сервера отладки. Если dbgs.exe запущен с требованием пароля, передайте его в параметре `password` при вызове `attach()`.

### Можно ли подключиться к удалённому серверу отладки?

Да, просто укажите URL удалённого сервера в `ONEC_DEBUG_URL`:

```json
{
  "env": {
    "ONEC_DEBUG_URL": "http://192.168.1.100:1550",
    "ONEC_INFOBASE_ALIAS": "DefAlias"
  }
}
```

Работа с удалённым сервером ничем не отличается от локального. Убедитесь что:
- Сервер отладки запущен на удалённой машине
- Порт доступен (не заблокирован файрволом)
- Есть сетевая связность с сервером
