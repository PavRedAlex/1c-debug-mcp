# FAQ — Часто задаваемые вопросы

## Общие вопросы

### Что такое MCP сервер?

MCP (Model Context Protocol) — протокол для интеграции AI-ассистентов с внешними инструментами. MCP сервер предоставляет набор инструментов, которые AI может вызывать для выполнения задач.

### Зачем нужен 1C Debug MCP Server?

Позволяет AI-ассистентам (Claude, Kiro и др.) управлять отладкой 1С: устанавливать точки останова, выполнять пошаговую отладку, просматривать переменные и вычислять выражения.

### Нужен ли Node.js?

**Нет.** Начиная с версии 2.0 сервер написан на Go и поставляется как единый бинарник без внешних зависимостей.

### Какие версии 1С поддерживаются?

1С:Предприятие 8.3 с поддержкой HTTP Debug Protocol (dbgs.exe). Протестировано на версии 8.3.27.

## Установка и настройка

### Как запустить сервер отладки 1С?

```bash
dbgs.exe --port=1550 --addr=localhost
```

### Где взять infobaseAlias?

Из файла `ibases.v8i`:
- Локальная база: обычно `DefAlias`
- Серверная база: имя базы на сервере 1С (например, `production_base`)

### Как настроить mcp.json?

```json
{
  "mcpServers": {
    "1c-debug": {
      "command": "C:\\path\\to\\1c-debug-mcp.exe",
      "env": {
        "ONEC_DEBUG_URL": "http://localhost:1550",
        "ONEC_INFOBASE_ALIAS": "DefAlias",
        "ONEC_CF_PATH": "C:\\path\\to\\src\\cf",
        "ONEC_LOG_LEVEL": "info"
      },
      "type": "stdio"
    }
  }
}
```

### Нужно ли выгружать конфигурацию?

Не обязательно, но рекомендуется. С `ONEC_CF_PATH` сервер автоматически резолвит `objectID` в имена модулей и авторезолвит `objectID` при установке точек останова.

## Отладка

### Как поставить точку останова?

```
mcp_1c_debug_set_breakpoints(
  moduleName="ОбщегоНазначения",
  moduleType="CommonModule",
  lines=[42]
)
```

`objectID` резолвится автоматически если настроены метаданные.

### Как поставить точку в расширении?

```
mcp_1c_debug_set_breakpoints(
  moduleName="_ДемоЗаказПокупателя",
  moduleType="ObjectModule",
  extensionName="_МоёРасширение",
  lines=[10]
)
```

Параметр `extensionName` указывает что искать в расширении, а не в основной конфигурации.

### Как поставить точку в форме?

```
mcp_1c_debug_set_breakpoints(
  moduleName="_ДемоЗаказПокупателя",
  moduleType="FormModule",
  objectID="uuid-формы-из-xml",
  lines=[15]
)
```

UUID формы берётся из `Forms/ФормаДокумента.xml`, атрибут `uuid` у элемента `<Form>`.

### Как работает pause?

`pause` устанавливает `breakOnNextLine=true` через `initSettings` — платформа остановится на следующей выполняемой строке **любой** цели. После остановки флаг автоматически сбрасывается.

```
mcp_1c_debug_pause()
// выполни действие в 1С
mcp_1c_debug_wait_for_stop()
```

### Почему точки останова не работают для внешних обработок?

Ограничение протокола 1С — внешние обработки имеют динамический `objectID`. Используйте `pause` + пошаговое выполнение.

### Как отладить серверную процедуру?

Серверные процедуры выполняются в цели `ServerEmulation` (файловая база) или `Server` (серверная база). Точки останова работают для обоих типов — просто укажите правильный `moduleName` и `moduleType`.

### Как получить стек вызовов?

Стек уже есть в ответе `wait_for_stop` (поле `callStack`). Также можно вызвать отдельно:

```
mcp_1c_debug_get_call_stack(targetId="...")
```

## Ошибки

### "ibInDebug — another debugger is connected"

Другой отладчик занял слот. Решения:
1. Закройте отладчик в Конфигураторе
2. Вызовите `force_detach` и `attach` заново
3. Перезапустите dbgs.exe

### "notRegistered"

Неправильный `ONEC_INFOBASE_ALIAS`. Проверьте имя базы в `ibases.v8i`.

### "Timeout waiting for stop event"

Выполнение не остановилось. Возможные причины:
1. Точка не сработала — проверьте `moduleName`, `moduleType`, `extensionName`
2. Код не выполнялся
3. Слишком короткий таймаут

### "No active debug session"

Не вызван `attach` перед другими командами.

### "Debug session is reconnecting"

Ping-цикл переподключается после сбоя dbgs.exe. Подождите несколько секунд и повторите `attach`.

## Логирование

### Как включить подробные логи?

```json
"ONEC_LOG_LEVEL": "debug",
"ONEC_LOG_FILE": "C:\\Logs\\1c-debug.log"
```

Уровни: `error` (только ошибки), `info` (ключевые события), `debug` (все HTTP запросы/ответы).

Файл перезаписывается при каждом перезапуске MCP-сервера.

## Разработка

### Как собрать из исходников?

```bash
cd 1c-debug-mcp/go
go build -o dist/1c-debug-mcp.exe ./cmd/1c-debug-mcp/
```

### Как добавить новый инструмент?

1. Добавить `HandleXxx` в `internal/tools/tools.go`
2. Зарегистрировать в `cmd/1c-debug-mcp/main.go` через `s.AddTool()`
3. Обновить документацию

### Где документация по протоколу отладки 1С?

Официальной документации нет. Используйте:
1. [onec-debug-adapter](https://github.com/akpaevj/onec-debug-adapter) — C# реализация
2. `vault/knowledge/logic/` — исследованный протокол
3. `raw_request` — для экспериментов

## Безопасность

- Не запускайте dbgs.exe на продакшен серверах
- Не коммитьте mcp.json с паролями в git
- Используйте только в изолированных средах разработки
